# Health Writeback

## Exercise write-back

Diary workouts to Apple Health and Health Connect (#1750), the `exercise` metric in `WritebackMetrics.ts`.

- `services/shared/exerciseWritebackPlan.ts` (pure) turns a day's `exerciseSessions` from the daily summary into `WorkoutWrite`s: only user-originated sources (shared `isUserOriginatedSource`; an empty source counts too), never calorie-linked sessions, preset sessions only when completed or finished. One workout per session; a preset session's window comes from its set times, else `finished_at` minus its duration, else noon (an entry without `entry_time` also goes to noon, never into the future). Active kcal is a measured `active_calories` as is, else the estimate minus `resting_calories` or BMR over the duration. The summary holds sets only, never the entry's notes.
- Activity type: shared `resolveHealthActivityType` (`shared/src/constants/healthActivityTypes.ts`): the exercise's `health_activity_type` override (the server resolves it: the exercise's current value while it exists, else the entry's own copy), else a guess from name stems, modality and category. One key maps to both an HKWorkoutActivityType and a Health Connect exercise type; labels live in `localization/healthActivityTypes.ts` and the web `HealthActivityTypeSelect`.
- `services/healthkit/exerciseWriteback.ts` saves through the patched `saveWorkoutSample` (`patches/@kingstinct__react-native-healthkit@16.2.0.patch`: `HKWorkoutBuilder` on iOS 17+, per-sample metadata, sync keys mapped to Apple's constants). Every workout and sample carries `SparkyExerciseWriteback` = the session key; replacing or removing deletes by that marker, per type, rather than by tracked UUIDs. Tracking is the list of keys per day (`writebackExerciseKeys:{date}`) plus a signature; a failed delete keeps its key for the next run.
- Before writing, a day's Apple Health workouts are read and any write another source covers for at least 80% of its time is skipped (this is what keeps Sparky Apple Watch sessions from being written twice). If that read fails nothing is written that run.
- Read side: the Workout reader and transformer skip workouts with the marker (`isOwnWrittenWorkout`; not the bundle id, because the dev seeders write workouts from the app on purpose), and once anything was written (`writebackExerciseFilterOwn`) the daily active energy and distance statistics leave marked samples out. A full removal clears that flag.
- Distances for rowing, paddle sports, skating and cross-country skiing need iOS 18 and are left out below it (`exerciseWriteTypes(iosMajor)`).
- Android, `services/healthconnect/exerciseWriteback.ts`: per session an `ExerciseSession` (exercise type from the same key, title, the summary as notes, zone offsets from the profile zone, one segment per timed set via shared `healthConnectSegmentFor`/`isSegmentAllowedInSession` in `shared/src/constants/healthConnectSegments.ts`, clipped and non-overlapping), an `ActiveCaloriesBurned` and a `Distance` over the same window. Fresh client ids per run (`sparky-exercise-…-<part>-<version>`), previous run's ids per type per day deleted first, like nutrition. Nothing is written without `ExerciseSession` read permission (the duplicate check); energy and distance are skipped when not granted, and the grants are part of the day's signature. The import skips sessions by that client id prefix (`isOwnWrittenExerciseRecord` in `healthconnect/dataTransformation.ts`, before enrichment and in the transformer), and once anything was written the daily active/total calorie and distance aggregates are re-run without this app's origin when it contributed (`aggregateWithoutOwnWrites` in `healthconnect/index.ts`). No permission-version bump: the metric is new, so nobody has it on yet.
- Device checks still owed: on iOS that a re-save replaces rather than duplicates, the builder save on a locked phone, and that removal never reaches the watch app's workouts; on Android that segments and zone offsets show in Health Connect, and that the second aggregate pass keeps other apps' totals. The Play Console health declaration must list the new write permissions before release.
